1. Game overview

ROTS is a Bevy 0.20 multiplayer game with a native client (Steam) and a web/WASM client. Players log in with Steam, Discord or au.2143.me, or play as a guest. This page is its living design doc: it starts with how the systems connect, and gameplay and systems sections get added here over time.

3. Enter the game

  1. The client calls POST /auth/api/v1/play with its session cookie or token.
  2. The authserver sends the update-with-start play to that login's session workflow (10 s bound).
  3. The session asks the coordinator to assign a slot: the slot the character is already present on, else the preferred one, else the least loaded. The pick is reserved for 360 s, unless the character is already on it.
  4. The session mints an EdDSA ticket with srv = slot, valid 300 s.
  5. The response is {ticket, expires_at, character_id, kind, server:{slot, udp, ws_path}}.
  6. The client connects to that slot. The game server verifies the ticket offline with the public key and checks srv.
  7. The game server calls join on :8001 and the player is admitted or refused (already_on_other_server). The coordinator signals the session present.

5. Failure behaviour

EventWhat players seeRecovery
Temporal down/play returns 503 temporal_unavailable; new joins are refused. Players already in a game keep playing.The worker reconnects every 10 s; workflow state is intact in temporal-db.
Authserver restartBrief errors on login, Play and new joins; players already in a game keep playing.None needed: the authserver is stateless, no state is lost.
Game server crashIts players drop to the menu.The pod restarts with a new boot_id; the coordinator clears its players, who can Play again.
Login session ended (logout, or replaced by a new login)A late connect or join is refused: 409 session_ended on the internal join.Play again from the menu, which starts a new session.
No healthy game servers/play returns 503 no_game_server.A slot becomes healthy again on its next heartbeat.

6. How this doc stays current

  • Any PR that changes a flow, port, service or state rule updates this page in the same PR. A design change made here first is implemented in code in the same PR.
  • The reviewer checks the page on the PR preview at https://rots-<PR>.john2143.com/design.html.
  • Dashed arrows become solid when their PR lands.
  • CI runs scripts/check-design-doc.py: every in-page link must resolve, and the page must stay script-free.
