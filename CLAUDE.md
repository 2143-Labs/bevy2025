# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is ROTS, a multiplayer Bevy game with procedural terrain generation and physics-driven characters. Features include:
- Procedurally generated terrain using Perlin noise
- Avian 3D physics engine integration, with a shared deterministic character controller
- FreeCam/ThirdPerson camera modes with smooth transitions
- UDP and WebSocket networking over a shared message layer, plus Steam networking
- A Nix-built client, headless server, and WASM/web client

## Workspace Layout

A three-crate Cargo workspace, Rust 2024 edition:

- `shared/` — code used by both sides: net library, config, components, physics/character controller, terrain generation. Generated networking code comes from `shared/build.rs`. Features: `udp`, `web`, `render`.
- `server/` — headless authoritative server (`lib.rs` + thin `main.rs`). Compiled without Bevy's default features.
- `client/` — the game. Feature flags: `steam` + `udp` + `clipboard` (default), `singleplayer` (runs the server in-process), `inspector` (egui world inspector), `web` (wasm build).
- `web/` — `index.html` for the wasm build; served by `packages.staticWebserver`.

## Build and Development Commands

### Nix Environment (Primary)

- **Development shell**: `nix develop` or `direnv allow`
- **Build client**: `nix build .#client` → `result/bin/client`
- **Build server**: `nix build .#server`
- **WASM + web bundle image**: `nix build .#staticWebserver`
- **Run**: `nix run .#client`
- **Container image**: `nix build .#container`

`flake.nix` uses naersk with a rust-overlay toolchain, so the dev shell and the packaged builds share one rustc. Bevy 0.20 needs rustc >= 1.97.1.

### Cargo (Alternative)

- **Check everything**: `cargo check -p shared -p server -p client`
- **Build**: `cargo build --release`
- **Run**: `cargo run -p client` / `cargo run -p server`
- **Format**: `cargo fmt`; **Lint**: `cargo clippy`

Note: `tokio` is currently reachable only through the `steam` feature, while `client/src/main.rs` uses it for every non-`web` build. A native build must therefore keep default features (or `steam`) enabled; `--no-default-features` without `steam` does not compile.

### WASM

`Makefile` drives the wasm pipeline (`build`, `serve`, `assets`, `print_size`, `clean`). The `wasm-bindgen` crate version in `Cargo.lock` must exactly match the `wasm-bindgen` CLI that nixpkgs supplies — both are currently 0.2.129. If you bump one, bump the other.

## Architecture

- **Shaders** live in `client/assets/shaders/` and are written in WESL (`.wesl`), which Bevy 0.20 uses instead of the old naga_oil dialect. Plain WGSL files with no preprocessor directives also work. `grass.wesl` and `water.wesl` are custom `ExtendedMaterial<StandardMaterial, _>` extensions handled in `client/src/grass.rs` and `client/src/water.rs`.
- **Networking**: `shared/src/netlib.rs` plus code generated by `shared/build.rs`. Client and server exchange postcard-encoded messages over UDP/WebSocket; `EventToClient`/`EventToServer` are generated enums. Generated `drain_incoming_events` tolerates a missing `NetworkingResources` resource (singleplayer paths don't always insert it).
- **Character controller**: `shared/src/character_controller.rs` is shared between client prediction and server simulation. `MovementAction` is wire-serialized — keep its field types stable.
- **Assets**: `client/src/assets.rs` declares `AssetCollection`s loaded during `GameState::AssetLoading`. A missing or mis-cased path silently stalls that state, because the loading state has no failure transition — asset paths must match the files under `client/assets/` exactly.
- **Physics**: terrain uses a trimesh collider built from the generated mesh; characters use capsule colliders with a kinematic controller.

## Technical Details

- Requires graphics libraries (Vulkan, Wayland, ALSA) on Linux; the flake provides them.
- `[profile.release.package.client] opt-level = "z"` keeps the wasm artifact small.

## CI/CD

`.github/workflows/build_nix.yml` runs on a self-hosted NixOS runner:

- Windows builds via cargo

## Physics (Avian 0.8)

- `PhysicsPlugins::default()`, `Gravity(Vec3)` resource
- `RigidBody::{Static, Dynamic}`, `Collider::sphere/trimesh_from_mesh/cuboid/capsule`
- Collision events: `CollisionStart`/`CollisionEnd`; `Collisions`, `ColliderOf`, `Position`, `Rotation`, `TransformInterpolation`
- Queries: `SpatialQuery`, `ShapeCaster`, `SpatialQueryFilter::with_excluded_entities`
- 0.8 renamed the precision aliases (`Scalar`→`Real`, `Vector`→`RVector`, `Vector2/3`→`RVec2/3`), removed the `f32`/`simd` features, and made `Vector`/`Vector2`/`Vector3` crate-private. This workspace is single-precision only (`parry-f32` everywhere), so use glam's `Vec2`/`Vec3`/`f32` directly rather than avian's aliases.

## Bevy Migration Notes

**0.15→0.16:** `Query::single()`→`Result`, `Parent`→`ChildOf`, `EventWriter::send()`→`write()`, systems return `Result`, no-std support.

**0.16→0.17:** `EventWriter`/`Reader`→`MessageWriter`/`Reader`, rendering moved to `bevy_camera`/`bevy_shader`/`bevy_light`, `Handle::Weak`→`Handle::Uuid`, `RenderStartup` vs `Plugin::finish`, `StateScoped`→`DespawnOnExit`, cursor types `bevy_winit`→`bevy_window`, conservative system parallelism, web `RUSTFLAGS` required.

**0.18→0.19:**
- `TextFont.font` became `FontSource` (`.into()` from a `Handle<Font>`), `font_size` became `FontSize::Px(..)`
- `SceneRoot`→`WorldAssetRoot`, `Scene`→`WorldAsset` (`…#Scene0` asset labels unchanged)
- `bevy::render::experimental::occlusion_culling`→`bevy::render::occlusion_culling`
- `PointLight`/`DirectionalLight` `shadows_enabled`→`shadow_maps_enabled`
- `SystemCondition::or`/`and` deprecated in favour of `or_else`/`and_then`

**0.19→0.20:**
- naga_oil is gone; shaders are WESL: `#import a::b`→`import a::b;`, `#ifdef X`→`@if(X)`, `#{MATERIAL_BIND_GROUP}`→`constants::MATERIAL_BIND_GROUP` in the `@group` position
- WESL module paths mirror source paths: `bevy_pbr::X`→`bevy_pbr::render::X`, `bevy_pbr::prepass_io`→`bevy_pbr::prepass::io`, `pbr_deferred_functions`→`bevy_pbr::deferred::functions`
- `alpha_discard` takes `(material_flags, alpha_cutoff, output_color)`
- `SystemCondition::or`/`and` removed — use `or_else`/`and_then`
- `World::inspect_entity` yields `(ComponentId, &ComponentInfo)` tuples
- avian 0.8: precision aliases renamed, `f32`/`simd` features removed (see the Physics section)
- `Interaction` is deprecated in favour of `Hovered`/`Pressed` (still functional; not yet migrated here)
