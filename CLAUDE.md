# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is ROTS, a multiplayer Bevy game with procedural terrain generation and physics-driven characters. Features include:
- Procedurally generated terrain using Perlin noise
- Avian 3D physics engine integration, with a shared deterministic character controller
- FreeCam/ThirdPerson camera modes with smooth transitions
- UDP and WebSocket networking over a shared message layer, plus Steam networking
- A Nix-built client, headless server, and WASM/web client

## Workspace Layout

A three-crate Cargo workspace, Rust 2024 edition:

- `shared/` — code used by both sides: net library, config, components, physics/character controller, terrain generation. Generated networking code comes from `shared/build.rs`. Features: `udp`, `web`, `render`.
- `server/` — headless authoritative server (`lib.rs` + thin `main.rs`). Compiled without Bevy's default features. Every server starts through `run_server(base_plugins, runtime, ServerSettings)`; `ServerSettings.coordinator: Option<GameServerCoordinator>` (`ROTS_COORDINATOR_URL`, plus `ROTS_SERVER_SLOT` and `ROTS_COORDINATOR_TOKEN`) starts `coordinator::spawn_link`: one FIFO sender for gated joins (6 s budget), leaves and a 10 s heartbeat roster to the authserver's internal API. The connect path is `vet_connect_requests` → `poll_pending_joins` → `admit_players`. It is `None` for standalone servers and testing gyms. Server loops are capped by `SERVER_LOOP_WAIT` (5 ms).
- `client/` — the game. Feature flags: `steam` + `udp` + `clipboard` + `testing` (default; `testing` hosts a gym in-process via `server::host_testing_server`: the normal server startup on 0.0.0.0:2143 (UDP + WebSocket, axum on 2144), tickets disabled, flat map `TerrainParams::gym()`, and a LAN beacon to UDP broadcast port 2145 (`shared::gym`). Testing clients list discovered gyms on the home menu; a second "Enter testing" on one machine joins the local gym. Hosts must allow inbound UDP 2143 and listeners UDP 2145. The client hands the gym a plugin group without window/winit/log plugins. `BUILD_HASH` comes from `shared/build.rs` (git HEAD, or `ROTS_BUILD_HASH`; "unknown" in Nix builds)), `inspector` (egui world inspector), `web` (wasm build).
- `web/` — `index.html` for the wasm build; served by `packages.staticWebserver`.

## Build and Development Commands

### Nix Environment (Primary)

- **Development shell**: `nix develop` or `direnv allow`
- **Build client**: `nix build .#client` → `result/bin/client`
- **Build server**: `nix build .#server`
- **WASM + web bundle image**: `nix build .#staticWebserver`
- **Run**: `nix run .#client`
- **Container image**: `nix build .#container`

`flake.nix` uses naersk with a rust-overlay toolchain, so the dev shell and the packaged builds share one rustc. Bevy 0.20 needs rustc >= 1.97.1.

### Cargo (Alternative)

- **Check everything**: `cargo check -p shared -p server -p client`
- **Build**: `cargo build --release`
- **Run**: `cargo run -p client` / `cargo run -p server`
- **Format**: `cargo fmt`; **Lint**: `cargo clippy`

Note: `tokio` and `reqwest` are unconditional dependencies on native targets (`client/src/main.rs` runs every non-`web` build on a tokio runtime, and the auth module uses `reqwest`), so `--no-default-features --features udp` also builds.

### WASM

`Makefile` drives the wasm pipeline (`build`, `serve`, `assets`, `print_size`, `clean`). The `wasm-bindgen` crate version in `Cargo.lock` must exactly match the `wasm-bindgen` CLI that nixpkgs supplies — both are currently 0.2.129. If you bump one, bump the other.

## Architecture

- **Architecture page**: `docs/architecture.html` is the canonical diagram set — components, the play and presence sequences, the coordinator and session state machines, failure modes, environments and the local testing modes. Update it in the same PR as any change to those flows.
- **Shaders** live in `client/assets/shaders/` and are written in WESL (`.wesl`), which Bevy 0.20 uses instead of the old naga_oil dialect. Plain WGSL files with no preprocessor directives also work. `grass.wesl` and `water.wesl` are custom `ExtendedMaterial<StandardMaterial, _>` extensions handled in `client/src/grass.rs` and `client/src/water.rs`.
- **Networking**: `shared/src/netlib.rs` plus code generated by `shared/build.rs`. Client and server exchange postcard-encoded messages over UDP/WebSocket; `EventToClient`/`EventToServer` are generated enums. Generated `drain_incoming_events` tolerates a missing `NetworkingResources` resource (the local test server does not insert it).
- **Login, tickets and placement**: every `ConnectRequest` carries a game ticket, an EdDSA JWT signed by `rots-authserver` (served under `/auth`); the server verifies it offline and rejects with `ConnectRejected { reason }`. The server reads `ROTS_AUTH_URL` + `ROTS_TICKET_AUDIENCE` (or `ROTS_AUTH_DISABLED=1`; the hosted testing gym always disables it), and `ROTS_BIND_IP` / `ROTS_PORT` override `config.yaml`. Tickets carry the login session (`sid`) and the slot the coordinator assigned (`srv`): a server with `ROTS_SERVER_SLOT` set refuses a ticket for another slot, and a join is refused once that login session is gone (`ConnectRejected "session ended"`). The client's `client/src/auth/` module holds the shared login code (`AuthRequest` → HTTP, `AuthSession`, `GameTicket`, `AssignedServer`, `AuthState`); "Play now" posts `/api/v1/play` and connects to the `server.udp` / `server.ws_path` it gets back, while `--play-server host:port` skips login entirely (empty ticket, for a server running with `ROTS_AUTH_DISABLED=1`). The platform backends (`native` with `--auth-url`, `steam` for Steam Web API tickets, `web` for same-origin cookies and OAuth redirects) are registered only in `client/src/main.rs`. Sessions are never written to disk: web uses the HttpOnly rots_session cookie, native keeps the token in memory, and Steam builds sign in with a Steam ticket at startup.
- **Character controller**: `shared/src/character_controller.rs` is shared between client prediction and server simulation. `MovementAction` is wire-serialized — keep its field types stable.
- **Assets**: `client/src/assets.rs` declares `AssetCollection`s loaded during `GameState::AssetLoading`. A missing or mis-cased path silently stalls that state, because the loading state has no failure transition — asset paths must match the files under `client/assets/` exactly.
- **Physics**: terrain uses a trimesh collider built from the generated mesh; characters use capsule colliders with a kinematic controller.

## Local testing

Three modes, all through the same `run_server` path (see `docs/architecture.html#local`):

| Mode | How | Coordinator |
|---|---|---|
| Gym | client "Enter testing" hosts the server in-process on UDP/WebSocket 2143 (axum 2144): tickets off, flat map, LAN beacon on 2145. A second "Enter testing" on the same machine joins it on `127.0.0.1:2143`. | no |
| Local dedicated server | `ROTS_AUTH_DISABLED=1 nix develop -c cargo run -p server`, then `nix develop -c cargo run -p client -- --play-server localhost:25555` (Play now skips login; works offline) | no |
| Full stack | rots-authserver `nix develop -c ./scripts/dev-stack.sh`; `ROTS_AUTH_URL=http://localhost:8000 ROTS_TICKET_AUDIENCE=http://localhost:8000 ROTS_SERVER_SLOT=0 ROTS_COORDINATOR_URL=http://localhost:8001 ROTS_COORDINATOR_TOKEN=devtoken nix develop -c cargo run -p server`; `nix develop -c cargo run -p client -- --auth-url http://localhost:8000` | yes (local Temporal, UI `http://localhost:18233`) |

A second local game server in full-stack mode: `GAME_SERVER_SLOTS=2` on the stack and `ROTS_SERVER_SLOT=1 ROTS_PORT=25556` on the server; 25556 is also the first server's axum port (`port + 1`), so the second server's axum and WebSocket listeners fail to bind and only its native UDP play works. The web client needs the gateway's same-origin `/auth`, so test it on a preview.

## Physics (Avian 0.8)

- `PhysicsPlugins::default()`, `Gravity(Vec3)` resource
- `RigidBody::{Static, Dynamic}`, `Collider::sphere/trimesh_from_mesh/cuboid/capsule`
- Collision events: `CollisionStart`/`CollisionEnd`; `Collisions`, `ColliderOf`, `Position`, `Rotation`, `TransformInterpolation`
- Queries: `SpatialQuery`, `ShapeCaster`, `SpatialQueryFilter::with_excluded_entities`
- 0.8 renamed the precision aliases (`Scalar`→`Real`, `Vector`→`RVector`, `Vector2/3`→`RVec2/3`), removed the `f32`/`simd` features, and made `Vector`/`Vector2`/`Vector3` crate-private. This workspace is single-precision only (`parry-f32` everywhere), so use glam's `Vec2`/`Vec3`/`f32` directly rather than avian's aliases.

## Bevy Migration Notes

**0.15→0.16:** `Query::single()`→`Result`, `Parent`→`ChildOf`, `EventWriter::send()`→`write()`, systems return `Result`, no-std support.

**0.16→0.17:** `EventWriter`/`Reader`→`MessageWriter`/`Reader`, rendering moved to `bevy_camera`/`bevy_shader`/`bevy_light`, `Handle::Weak`→`Handle::Uuid`, `RenderStartup` vs `Plugin::finish`, `StateScoped`→`DespawnOnExit`, cursor types `bevy_winit`→`bevy_window`, conservative system parallelism, web `RUSTFLAGS` required.

**0.18→0.19:**
- `TextFont.font` became `FontSource` (`.into()` from a `Handle<Font>`), `font_size` became `FontSize::Px(..)`
- `SceneRoot`→`WorldAssetRoot`, `Scene`→`WorldAsset` (`…#Scene0` asset labels unchanged)
- `bevy::render::experimental::occlusion_culling`→`bevy::render::occlusion_culling`
- `PointLight`/`DirectionalLight` `shadows_enabled`→`shadow_maps_enabled`
- `SystemCondition::or`/`and` deprecated in favour of `or_else`/`and_then`

**0.19→0.20:**
- naga_oil is gone; shaders are WESL: `#import a::b`→`import a::b;`, `#ifdef X`→`@if(X)`, `#{MATERIAL_BIND_GROUP}`→`constants::MATERIAL_BIND_GROUP` in the `@group` position
- WESL module paths mirror source paths: `bevy_pbr::X`→`bevy_pbr::render::X`, `bevy_pbr::prepass_io`→`bevy_pbr::prepass::io`, `pbr_deferred_functions`→`bevy_pbr::deferred::functions`
- `alpha_discard` takes `(material_flags, alpha_cutoff, output_color)`
- `SystemCondition::or`/`and` removed — use `or_else`/`and_then`
- `World::inspect_entity` yields `(ComponentId, &ComponentInfo)` tuples
- avian 0.8: precision aliases renamed, `f32`/`simd` features removed (see the Physics section)
- `Interaction` is deprecated in favour of `Hovered`/`Pressed` (still functional; not yet migrated here)
